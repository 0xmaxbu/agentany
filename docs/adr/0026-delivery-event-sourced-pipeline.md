# 0026 - 投递事件溯源管道：事实事件落库 + 游标重放（分期）

日期：2026-08-17（/grill-with-docs 会话定稿，Q16–Q19）

## 状态

已接受（终态定档，分期实施；P1 = ADR-0025 本分支先行）

## 背景

多通道（IM 等）立项在即，触发完整投递管道。现状 EventBus 内存 fire-and-forget，重连丢帧是自认债务（eventbus.ts:3、#19 序列号）。审查中发现两个问题：字面「一切皆事件」会把 token delta 落日志（自造吞吐问题）；Redis 提案与崩溃封堵（ADR-0025 同事务设计）存在硬冲突。

## 决策

1. **事件分层**：**事实事件**（可重放：消息定稿/简报/卡/run 状态/title/done）落 SQLite 事件表（per-conversation 单调 seq，WAL）；**瞬态帧**（`block_delta`）内存直推、永不落日志——重放以 block_start+end 整块合成，投影等价。事实事件频率每轮 <10 条，SQLite 余量 100×+；IM 通道本就不要 token 流。
2. **投递皆事件、域表为真相**：管道做**投递层**事件溯源——事件行引用域行（messageId/questionId/runId），messages/hitl_questions/workflow_runs 保留为域真相，不重写为投影。日志记**域语义事件**（`message.completed` 而非 UI 帧）——前向兼容：将来审计/时间旅行立项可直接从同一日志建域投影（Phase 4）。
3. **Redis 否决**：① 事件追加必须与域变更**同 SQLite 事务**（ADR-0025 崩溃封堵依赖此），Redis 无法参与 → 双写 → 崩溃窗口回归；② 持久性倒挂（AOF everysec 崩溃丢 1s / appendfsync always 吞吐优势归零 / maxmemory 淘汰对日志致命）；③ 单进程无对手（ADR-0003 刻意单进程；ADR-0009 已明写无需 Redis）。EventBus/管道接口后留**多进程交换点**——届时 Redis Streams 为合理候选。
4. **通道模型**：每通道一个消费者 + 各自游标（channel_cursors 表）；**首次连接 = 快照**（GET messages/hitl）+ 游标续传，**重放范围 = 自日志起点**（非全史——P2 上线前历史靠快照端点）；SSE 重连 = 带游标补放再续实时。新订阅者防竞态序：**订阅 → 读位点 → 补放 → 去重**（commit 与 live 推送之间入线者靠去重收敛）。IM 适配器消费域语义事件做原生格式降级，事件 payload **内联完整内容**（日志低频、IM 要内容、免二次取）；投递语义 **at-least-once**（push 后游标推进前崩溃 → 重推），通道侧按 questionId/messageId 幂等。用户经 IM 答卡走既有 POST /messages + inReplyTo（ADR-0022，已通道无关）。
5. **分期**：**P1** 零 LLM 直投 + 崩溃封堵（ADR-0025，本分支）→ **P2** 投递日志 + 游标 + 重放（清 #19；run 卡刷新恢复随之免费）→ **P3** IM 通道适配器 → **P4** 可选域投影（审计/时间旅行立项才做）。

## 负决策

- 不做全量域事件溯源（「一切皆投影」的字面执行）：store.ts 20+ 方法与全部查询重写为投影，周级改造，而多通道的四个真实需求（离线补投/多通道并发消费/格式降级/通道无关应答）零一需要它——域表为真相（决策 2）。
- 不给 block_delta 落任何形式的日志（合并/懒写也不）——它是 web SSE 传输私有物，不是事件。

## 后果

- 事实事件表无限增长：单团队规模年量级 ~10⁵⁻⁶ 行，SQLite 无压力；保留策略（按低水位裁剪旧事件 + 游标下限）留为未来旋钮。内联 payload 与 messages 双存（存储 2×）为低频+免二次取的权衡，将来可切引用式。
- #19 序列号债务与 run 卡刷新不恢复在 P2 一次性清偿。
- 前端 `store/chat.ts` 帧处理在 P2 加游标/去重/乱序容错；e2e 契约类名不变。
- ADR-0025 的启动对账（brief_message_id 扫描）在 P2 被结构性取代（事件与域行同事务落库，无窗口）。
