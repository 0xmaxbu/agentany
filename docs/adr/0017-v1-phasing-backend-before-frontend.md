# v1 分阶段：后端先于前端，一步一步

固化 v1 的实现顺序：后端（用户/项目）先，前端重构后；分步做。

## 决策

v1 分阶段顺序：
1. **后端（用户/项目）先**：a. auth+users（ADR-0014 opaque token）→ b. projects+members（多对多+角色）→ c. 鉴权边界（角色/成员应用到路由）。
2. **前端重构后**：ADR-0015 三区 chat-centric shell + ADR-0016 shadcn(Radix)+Tailwind v4，含 #20（消息 blocks）+ 3 个 UX 痛点修复。

## 理由

- Q1：v1 先后端 CRUD——数据模型 / 鉴权边界不可逆性高，先钉死。
- 前端 shell / 管理视图依赖后端的用户/项目/鉴权模型；后端不定，前端无数据可绑。
- 一步一步：避免一次性大重构（前端重构规模大），分步降风险、每步可独立验收。

## 后果与已知债务

- 前端 UX 痛点（HITL 卡遮挡聊天 / 对话不流式 / 工具调用+thinking 不显示 → "发消息不知道服务器响应"）在 v1 后端完成前**暂不修**——记为已知债务，前端阶段（含 #20）统一修。
- guard rail：本 ADR 防止规划再次走偏冲前端。
