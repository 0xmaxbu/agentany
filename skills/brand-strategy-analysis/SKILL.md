# brand-strategy-analysis —— 战略分析方法论

本 skill 是 **brand-strategy-analysis 工作流**的执行深度指引。**编排（选角度→生成→验收，含 revise 循环）由代码管**；本 skill 管**怎么把角度深化成报告**。

## 输入

- 读 `brand-research/<brand>-<region>/research-report.md`（调研）+ `angles.json`（候选角度）。
- 用户选定角度（id 列表或 "all"）。

## 角度深化（每个选中角度）

核心洞察 → 战略逻辑（证据链 [F][P]→[I]）→ 机制分析（为什么）→ 逻辑验证（条件/反例/可行性）→ 设计工作范围 → 服务范围映射 → 预期效果。

## 报告红线（必须严守）

**报告是战略交付物，不是设计方案。** 一律不得出现：具体配色（色值/色相/主色名）、具体字体/字标方案、具体图形/符号/IP 造型、具体工艺（烫金/专色等）/材质/版式、任何"应该长什么样"的表述。

设计相关内容只允许写**工作范围与目标**："需要建立支撑 X 定位的视觉识别体系 / 重构包装体系以解决 Y"。一旦报告预设样式，客户会对实际设计产生不现实预期。

## 报告结构（写 `reports/<brand>-<region>-战略升级报告.md`）

1. 执行摘要
2. **核心洞察**（2-3 个最独到发现，说明"为什么别人没看到"+ [F][P] 依据）
3. 调研发现（行业/竞争市占/差异/诊断/消费者）
4. 品牌机会点（经逻辑验证）
5. **选定角度深化**（每个一节：洞察→逻辑→机制→验证→工作范围→服务映射→预期）
6. 视觉识别系统工作范围（不给样式）
7. 包装设计工作范围（同上）
8. 服务范围与交付
9. 落地路线与优先级

## 规则

- 每个结论带来源、三层证据分离、方案经逻辑验证。
- 中文输出。
- **revise**（用户验收退回）：按 comments 修订重生成报告。
