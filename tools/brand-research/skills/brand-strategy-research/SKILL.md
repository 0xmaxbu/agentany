# 品牌战略升级调研工作流

业务背景：为**品牌设计、包装、视觉系统**的设计及制作服务客户。切入角度必须**设计导向**（视觉/包装/VI 可落地），报告要充分考虑我们的服务范围。

## 工具

- `web_search(query, max_results?)` — Tavily 搜索，返回标题/URL/内容摘要
- `web_extract(urls[])` — 提取网页正文（深读官网/报告/竞品页）
- `web_crawl(url, max_depth?, limit?)` — 爬取站点
- 内置 `read`/`write`/`edit`/`bash` — 读写文件、建目录

## 阶段

### 1. 输入

- 参数：`/skill:brand-strategy-research <品牌名> [地区]`
- `<品牌名>` 必填；`<地区>` 可选，**缺省为"重庆"**
- 品牌+地区是本次研究范围（地区市场为研究重点之一）；输出目录用 `<品牌>-<地区>` 或 `<品牌>`（多品牌则向用户确认）

### 2. 调研（web_search + web_extract，必要时 web_crawl）

调研 5 块，**每条信息记来源 URL**，事实 `[F]` vs 推断 `[I]` 分开标注：

1. **行业基本面**：市场规模/增速/趋势、高/中/低端结构、渠道格局、新锐品牌动向；**地区市场**（重庆）：行业规模、增长、本地消费特点
2. **竞争格局与市场占有率**：3-5 个直接竞品/头部品牌 —— 定位、视觉语言、包装、渠道、价格带、**门店数/市占率**；地区内（重庆）竞争态势：谁在本地占主导、本地品牌 vs 全国连锁
3. **品牌差异分析**：目标品牌 vs 竞品在 定位/产品/价格/视觉/渠道/心智 上的**差异点与空白**（差异化机会）
4. **品牌诊断**：目标品牌定位/产品线/价格带/视觉资产（logo/色彩/字体）/包装现状/渠道/消费者认知与口碑
5. **消费者**：目标客群画像（含地区消费者）、需求、购买决策因素

写调研笔记到 `.work/brand-research/<brand>/research-notes.md`：分节、每条带来源 URL、事实与推断分开。

### 3. 产出切入角度（需逻辑验证）

综合调研，产出 **4-6 个"品牌战略升级切入点"**。每个角度必须完成**逻辑分析推理验证**后才能列为候选：

- **标题**：一个战略方向短语
- **战略逻辑**：完整证据链 —— 数据/证据（注明来源）→ 推断 → 机会点
- **逻辑验证**：显式验证 —— 假设是否成立？是否有反例？是否与其它证据矛盾？可行性/风险？
- **设计工作范围**：该角度需要设计/制作**哪些工作项**（如：视觉识别体系重设、包装体系重构、超级符号建设、延展应用规范），并说明每项要解决的**战略/认知问题**；**不得给出具体设计样式**（配色/字体/图形/工艺/版式/材质等具体方案）
- **服务范围映射**：该角度对应我们可提供的设计与制作服务项
- **可行性**：成本/风险/见效速度（高/中/低）

角度维度参考：品牌定位重塑 / 视觉识别(VI)焕新 / 包装体系升级 / 超级符号·视觉锤 / 客群聚焦与调性重塑 / 品类占位与差异化视觉 / 渠道场景化视觉适配 / 品牌叙事与信任感建立。

**验证要求**：每个角度必须能用数据/证据支撑，逻辑上自洽；证据不足或逻辑有漏洞的角度不得进入候选。写 `angles.md` 并**完整展示给用户**（含逻辑验证摘要）。

### 4. 用户选择

- 在 Pi 会话中向用户提问，**结束当前回合等待回复**："请回复要深入的角度编号（可多选，如 1,3,5），或回复'全部'。"
- 用户回复后解析编号并保存到 `.work/brand-research/<brand>/selection.md`。

### 5. 生成报告

按选定角度生成 `reports/<品牌>-<地区>品牌战略升级报告.md`，结构：

1. **执行摘要**
2. **调研发现**：行业（含地区）/ 竞争与市场占有率 / 品牌差异 / 品牌诊断 / 消费者
3. **品牌机会点**（经逻辑验证）
4. **选定角度深化**：每个角度一节 —— 战略逻辑（证据链）→ **逻辑验证**（假设/反例/一致性/可行性）→ **设计工作范围**（需设计/制作哪些工作项 + 要解决的战略问题）→ **服务范围映射**（对应我们的服务项）→ 预期效果
5. **视觉识别系统工作范围**：需设计什么、解决什么战略问题（不给具体样式）
6. **包装设计工作范围**：同上
7. **服务范围与交付**：把核心建议映射到我们的服务项（品牌设计/包装设计/视觉系统/设计制作/打样印刷），说明每项交付什么、如何推进
8. **落地路线与优先级**（阶段/里程碑/验收标准）

规则：每个结论带来源标注，事实与推断分离，方案必须经过逻辑验证；写入后向用户报告路径。

## 报告红线（重要）

**报告是战略交付物，不是设计方案。** 具体设计样式是设计师的工作，报告一律**不得出现**：

- 具体配色（色值/色相/主色名）
- 具体字体/字形/字标方案
- 具体图形/符号/IP 造型
- 具体工艺（烫金/双层杯/专色等）/ 材质 / 版式
- 任何"应该长什么样"的表述

报告中设计相关内容只允许写**工作范围与目标**："需要建立一套支撑 X 定位的视觉识别体系 / 需要重构包装体系以解决 Y 问题"，具体方案由设计团队在后续设计阶段提案。一旦报告预设样式，客户会对实际设计产生**不符合现实的预期**，因此红线必须遵守。

## 规则

- **结论必须有证据**（来源 URL）；无证据的内容标注"推断"，不得编造数据
- **所有方案必须逻辑验证**：证据链完整、无反例、不与调研矛盾，验证过程写入报告
- 调研区域以输入地区（缺省重庆）为研究重点之一
- 所有调研走 `web_search`/`web_extract`/`web_crawl`，不编造
- 中文输出（客户为中文语境）
- 若搜索工具报错（如 key 缺失），报告错误并停止，提示用户检查 `.env` 的 `TAVILY_PROXY_API_KEY`
- 目录 `.work/`、`reports/` 不存在则先 `mkdir -p`
- 跑完后提示可把本次经验沉淀到 `learnings/`
